Getting started · Agents

Eight agents: six from the kit, two built in

SF-SDLC works with eight agents. Six come with the kit: the discovery & design agent (existing orgs checked against the discovery pack, then the fit-gap and HLD), MapShift (one org's subjects, case rules, letters and forms mapped onto the target org for a harmonization), the BRD agent (meeting transcripts), the solution architect (the whole codebase and diagrams), the code reviewer (Code Analyzer and the Salesforce coding rules, independent of whoever wrote the code) and QA (test runs and browser sessions). Two are built into your coding agent: the planner (plan mode) and the developer (the agent that edits your code) already come with Claude Code, Cursor and the others, and the kit makes them follow the spec-driven format and the project rules automatically. Each stage still writes a draft and stops; a person approves it before the next stage starts.

No duplicate agents to learn: you plan and build with your coding agent directly, and the kit adds only the agents it does not already have. Stages never call each other. They hand off through files in your repository, linked by one ID chain, so you can stop, review, edit or re-run any stage on its own and still trace a release back to the meeting it came from.

Discovery & design agent Kit agent

Stage D · Existing orgs: discovery validation, fit-gap, HLD

What it does

  • Takes a dated, read-only snapshot of each org with sf-sdlc discover: data model, automation, code, profiles and permission sets, sharing, integrations, packages, licences, limits, recent setup changes
  • Reads the discovery pack in its own context and checks every statement against the org: confirmed, partly holds, contradicted, stale or not verifiable, each with its evidence
  • For a merge or harmonization, compares the orgs and records keep, bring, merge or retire per component, with the conflicts a merge always hits
  • Drafts the current-state assessment, the fit-gap (fit to standard first, declarative before code) and the HLD the solution architect continues
Reads
Workshop notes, call transcripts, current-state documents; one or more existing orgs, production included, read-only
Writes
docs/sdlc/00-discovery/: snapshots, claim register (CLM), org comparison, current state, fit-gap (FG); 03-architecture/HLD.md draft
Tools
read-onlyMetadata queries and counts through the sf CLI, read-only MCP tools. No record data, no user names, never a change to an org.

Try it

/sf-sdlc:discovery target-prod source-prod docs/sdlc/00-inputs/discovery/

Stops with drafts. After a person reviews them: /sf-sdlc:brd with the discovery outputs as inputs, or /sf-sdlc:architecture to continue the HLD.

MapShift agent Kit agent

Stage M · Map & migrate: case mapping and migration for org harmonization

What it does

  • Reads both orgs' metadata read-only: case subjects and reasons, record types, picklists, assignment and escalation rules, email templates, web-to-case forms and document templates
  • Builds the mapping from the source org onto the target org's case model: subject to Case Reason, rule to rule, field to field, each marked keep, map, merge or retire
  • Flags every mapping the business has to decide, instead of guessing it
  • Lists every letter and form that must be rebuilt in the target org, with the fields each one uses, ready for the build and the data migration
Reads
The approved fit-gap and HLD from the discovery agent; both orgs' metadata, read-only
Writes
docs/sdlc/00-discovery/mapping/: mapping register (MAP), decisions for the business, rebuild list for letters and forms, migration field map
Tools
read-onlyMetadata queries through the sf CLI and Metadata Grounding. No record data, never a change to an org.

Try it

/sf-sdlc:mapshift target-prod source-prod cases

Stops with drafts. After the business signs off the mapping: /sf-sdlc:stories for the rebuild work, then /sf-sdlc:architecture.

Solution architect Kit agent

Stage 3 · Architecture

What it does

  • Starts from a baseline of what already exists in the code and the org
  • Writes the HLD, a low-level design per story or Jira ticket, and ADRs for each decision
  • Marks every component New, Changed, Unchanged or Removed in components.json
  • Draws editable draw.io diagrams to Salesforce's own standard, exported to PNG, SVG or PDF
Reads
Approved BRD and stories, the codebase, the baseline inventory, a non-production org
Writes
HLD.md, LLD-US-*.md, ADRs, components.json, .drawio
Tools
All tools; the shell only for read-only inspection. Uses Metadata Grounding and SObject Reads when connected.

Code reviewer Kit agent

Stage 6 · Code review

What it does

  • Never saw the build, so it does not share the author's assumptions
  • Runs the official Salesforce Code Analyzer and the kit's source checks on the changed files
  • Reads every changed file in full: sharing, user mode, SOQL injection, secrets, bulk safety, tests
  • Gives a verdict: Approve, Approve with conditions, or Changes required
Reads
The change delta, the spec and acceptance criteria, the coding rules
Writes
review.md with a verdict, nothing else
Tools
read-onlyRead, Glob, Grep, Bash. No file edits, no org changes.

Try it

/sf-sdlc:review
/sf-sdlc:review feature/US-04-02-revenue-chart

A person reads the verdict and decides. Fixes go back to the developer, then review again.

QA agent Kit agent

Stages 7 · 9 · Test design, runs, UI, re-test

What it does

  • Designs positive, negative, boundary, permission, bulk and UI cases from acceptance criteria
  • Runs Apex and Jest tests through the Salesforce CLI and checks coverage against the target
  • Tests an LWC or any page in a real browser (Playwright) in a sandbox, with a screenshot per result
  • Logs defects with steps and evidence, and re-tests fixes with the regression set
Reads
Stories, acceptance criteria, LLDs, a non-production org
Writes
TC-*, CSV for Xray, Zephyr or TestRail, TR-* with screenshots, DEF-nnn
Tools
All tools. The browser never opens a production org; Jira bugs only after a preview and a yes.

Try it

/sf-sdlc:test-cases US-04-02
/sf-sdlc:ui-test revenueChart on the Account page in acme-uat

Stops with the report. A person accepts the results; failures become defects to fix and re-test.

Why these eight? The kit adds an agent only where your coding agent does not already have one and a separate context helps: long inputs (a discovery pack and org snapshots, two orgs' metadata to map, transcripts, a whole codebase, test runs and browser sessions) and an independent review, by a reviewer that never saw the build. Planning and building already come with Claude Code, Cursor and the others, so the kit does not duplicate them; it makes them follow the spec-driven format, the coding rules and the Salesforce skills installed in your project. Setup, stories, deployment and release run in your conversation, where you can see and steer them. Every stage writes a draft and stops.
