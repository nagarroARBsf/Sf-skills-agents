Session tracing with Langfuse

SF-SDLC can send every Claude Code session to Langfuse, the open-source LLM observability platform. Each turn becomes a trace you can open: what was asked, every model response and tool call on a timeline, how long each step took, the tokens used and what it cost, plus dashboards across the whole team.

What you see in Langfuse

One trace per turnNamed Claude Code - Turn N, with your prompt as input and Claude's answer as output. Turns of one session are grouped under Sessions.
Every model responseA generation per response, with the model name and input, output and cache tokens. Langfuse prices them, so cost appears per step and per turn.
Every tool callBash, file edits, MCP and browser tools as spans with their input and result. Failed calls are marked as errors.
Team dashboardsCost by model, by user and by use case; trace and observation counts over time, filtered by the claude-code environment.

Set up tracing

Langfuse runs on your own machine or server with Docker, so prompts, code and outputs stay inside your network. You need Docker with Docker Compose v2 (Docker Desktop includes it) and Git.

Start Langfuse with Docker

Clone Langfuse and start it. The first start pulls the images (web, worker, Postgres, ClickHouse, Redis and MinIO) and takes a few minutes.

git clone https://github.com/langfuse/langfuse.git
cd langfuse
docker compose up -d

docker compose ps        # all services "running" / "healthy"

Open http://localhost:3000, sign up (the account is local to your server), and create an organisation and a project, for example Claude tracing.

Create API keys

In the project: Settings → API Keys → Create new API keys. Copy the public key (pk-lf-…) and the secret key (sk-lf-…). The secret is shown once.

Add the keys to the project .env

The .env.sample that setup creates already lists the three names. Fill them in .env, which is git-ignored and which Claude is not allowed to read.

LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_BASE_URL=http://localhost:3000

Turn tracing on

Tracing is off until you switch it on, per person, in .claude/settings.local.json (not committed). Then restart Claude Code.

{
  "env": {
    "TRACE_TO_LANGFUSE": "true"
  }
}

Check it works

Ask Claude anything, let it finish, then open Tracing in Langfuse: the turn appears within seconds. For cost, open Dashboards → Langfuse Cost Dashboard and filter on the claude-code environment. If nothing arrives, add "CC_LANGFUSE_DEBUG": "true" next to TRACE_TO_LANGFUSE and read ~/.claude/state/langfuse_hook.log.

Useful Docker commands, run in the langfuse folder:

docker compose logs -f langfuse-web     # follow the web server log
docker compose stop                     # stop; data is kept in Docker volumes
docker compose pull && docker compose up -d   # update to the latest Langfuse
docker compose down -v                  # remove Langfuse AND all its data

Before you share the server with your team, change every value marked # CHANGEME in Langfuse's docker-compose.yml (database passwords, NEXTAUTH_SECRET, SALT, ENCRYPTION_KEY) and put it behind HTTPS. Langfuse recommends at least 4 CPU cores and 16 GB of memory for a shared server. Then point everyone's LANGFUSE_BASE_URL at it. Prefer the hosted service? Use https://cloud.langfuse.com (or https://us.cloud.langfuse.com) as the base URL instead.

What is sent. Your prompts, Claude's answers and tool inputs and outputs (each clipped at 20,000 characters) go to the Langfuse server you configured, and nowhere else. The keys are read at run time and never printed or logged. Tracing runs after Claude has finished a turn, and a tracing failure never interrupts your session.
