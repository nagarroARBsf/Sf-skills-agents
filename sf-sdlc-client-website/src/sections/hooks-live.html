Hooks in action

Hooks are small Node.js programs that Claude Code runs at fixed points in a session: when it starts, before and after every tool call, and when Claude finishes. They see exactly what the agent is about to do and can allow it, ask you, block it, or add a note the agent must read.

Pick a scenario to watch one tool call travel through the hooks. The messages are shortened from the real ones.

What each hook does

EventHandlerRuns whenWhat it does
SessionStartsession-startA session opensGives Claude the project facts: DX project, config, default org and its class, branch, which artifacts exist, hook mode
PreToolUse · Bashpre-bashBefore any sf, git or sf-sdlc commandOrg guard (classifies the target org), branch guard, commit gate (secrets, then Code Analyzer on staged files)
PreToolUse · Write / Editpre-writeBefore a file is writtenSecret guard: blocks credential files and content that holds tokens or keys
PreToolUse · MCPpre-mcpBefore a Hosted MCP or browser toolAsks before a tool that can change the org, and before the browser opens a production-class org
PostToolUse · Write / Editpost-writeAfter a file is writtenFast Salesforce source checks (SOQL/DML in loops, sharing, hard-coded IDs, SeeAllData, LWC innerHTML…) fed back to Claude
PostToolUse · Bashpost-bashAfter a shell commandWrites org-affecting commands to the audit log .sf-sdlc/audit.jsonl
PostToolUseFailure · Bashbash-failureWhen an sf command failsAudit entry plus a likely cause: row locks, missing dependency, coverage, governor limits, duplicates
Stopstop (and Langfuse)Claude finishes a turnEvidence gate: no ticked task without evidence (hooks.strictEvidence). Also sends the turn to Langfuse when tracing is on

The org guard and the secret guard enforce in every mode. The others follow hooks.mode: observe reports what would be blocked, enforce blocks it. A hook that crashes asks you instead of silently allowing. The full list of guards is under Guards and hooks.
