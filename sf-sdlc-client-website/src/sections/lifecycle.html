Using the plugin

The SDLC lifecycle

Five stages run in a kit agent: discovery of existing orgs, requirements, architecture and QA because they read large inputs or produce long tool output, and code review so it is independent of the author. Planning and building use your coding agent's own plan mode and editing, in the kit's spec-driven format. The rest run in the main conversation, each guided by its sdlc-* skill and the project rules. Every stage writes a draft and stops for a person. Any document or Jira template can be replaced by your team's own copy in paths.templates (sf-sdlc templates list, sf-sdlc templates copy <id|area|all>).

Traceability runs through one ID chain: BR-04 → FR-04.2 → US-04-02 → LLD-US-04-02 → TC-US-04-02-007 → TR-… → DEF-012 → DEP-005 → REL-1.4.0. /sf-sdlc:trace shows it at any time.

Every repeated mistake becomes a constraint. Instructions and skills are advisory; tests, Code Analyzer rules, hooks and quality gates are deterministic. A defect closes only when its record names the constraint added (or says why none fits), and the review recommends the strongest check that would have caught a finding.
