How the pieces work together

A command either names one of the five agents (discovery & design, BRD, solution architect, code reviewer, QA) or tells Claude to follow a skill in the main conversation. Either way the method skill loads, with the coding rules and any Salesforce skills installed in the project; real work on Salesforce goes through the sf-sdlc CLI and the sf CLI, and org context (what metadata already exists, metadata schemas) comes from Salesforce Hosted MCP Servers. Hooks sit around every tool call.

CommandYou type /sf-sdlc:review US-04-02
Agentsdlc-code-review-agent: own context, read-only tools (Read, Glob, Grep, Bash)
Skills and rulessdlc-code-review, sdlc-workflow, Apex rules + installed Apex skills
CLIsf-sdlc analyze, delta → sf code-analyzer
Draftreport returned and saved as specs/US-04-02-…/review.md with a verdict, then stop
Hooks around every step: SessionStart prints project facts and instructions · PreToolUse runs the production-org, secret, branch, commit and hosted-MCP guards · PostToolUse runs source checks and writes the audit log · PostToolUseFailure explains deploy failures · Stop checks task evidence. Monitors report when a background deploy or test run changes state.
