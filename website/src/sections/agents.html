In action

The ten agents

SF-SDLC splits delivery into ten specialist agents, one per lifecycle stage. Each one runs in its own context with only the tools and skills its job needs, writes a draft, and stops. A person approves the draft before the next agent picks it up.

Agents never call each other. They hand off through files in your repository, linked by one ID chain, so you can stop, review, edit or re-run any stage on its own and still trace a release back to the meeting it came from.

Why separate agents? A fresh context per stage keeps each agent focused and stops one stage's assumptions leaking into the next. Narrow tool lists matter too: the reviewer cannot quietly fix what it is judging, and the BRD agent cannot touch an org. Each agent loads the sdlc-* method skill for its stage plus the Salesforce skills installed in your project.
